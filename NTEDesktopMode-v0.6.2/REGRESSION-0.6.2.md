# 0.6.2：原生输入开关与按钮释放

用户反馈：键盘和地图拖动正常，但多个界面的按钮在点击后停留在按下状态，未触发功能。按用户要求，本次不启动游戏，由用户完成实际游玩验证。

## 分析与取舍

地图能正常拖动，不能据此认定整个原生鼠标通道都缺少 release。现有实现中发现两项风险：0.6.1 在输入初始化后延迟切换 UIKit 分类，可能改变已创建的输入兼容状态；hover 手势结束时清空坐标，可能使后续原生 mouse-up 读不到之前的有效位置。没有采集本次实际事件序列，因此没有把这些静态发现当成唯一运行时原因。

按照用户要求，最终实现只设置原生开关和保留必要坐标适配。不实现插件侧触摸过滤、按钮释放补发或按钮状态修补。开发期间尝试过的触摸集合过滤及生命周期路由未进入此版本。

## 最终改动

1. **启动时设置原生间接输入能力。** 保留 0.6.1 的 C++ 初始化顺序修复，在游戏继续初始化前设置三项 UIKit 原生能力查询，不再在交互过程中延迟切换。
2. **由游戏原函数过滤鼠标的触摸副本。** 动态解析器先核对 `FIOSView -HandleTouches:ofType:` 中调用 `UITouch.type`、比较 type=3 并跳过处理的分支。观察器仍将原触摸集合、原对象、原参数完整交给原函数，不删事件、不改 phase/type、不重排 down/up。
3. **关闭原生 `InputSettings.bUseMouseForTouch` 配置。** 根据反射属性的原生 setter 解析字段偏移与位掩码，读取已初始化的 InputSettings 默认对象，仅清除此配置位。保留相邻配置、不调用 SaveConfig，不修改磁盘配置。若类、对象或布局未验证则不修改。
4. **release 不包装 GameController 回调。** 原生键盘与鼠标 handler 由游戏直接持有，按钮按下、抬起及点击行为都由游戏执行。诊断包装器保留为显式诊断构建使用；当前 release 中不存在三个硬件 handler setter selector。
5. **保留地图坐标适配。** 仍观察真实间接指针位置，供未捕获状态的原生光标查询使用。hover 的 inside-view end/cancel 不清除最后有效位置；失焦和越界仍会使位置无效。
6. **缩短原生输入初始化等待。** 首次维护任务延迟约 0.25 秒，初始化期间约每秒重试，原生输入与光标就绪后恢复约三秒周期。

## 本地静态核对

同一解析器在本地 1.4 和 1.5 主程序中均确认：

| 项目 | 1.4 | 1.5 |
| --- | --- | --- |
| 原生 type=3 过滤分支 | 存在并核对 selector 与跳过分支 | 存在并核对 selector 与跳过分支 |
| InputSettings 类缓存 | 动态定位成功 | 动态定位成功 |
| bUseMouseForTouch 属性 | 原生 setter 为字段 `+0x48` 的 `0x4` 位 | 原生 setter 为字段 `+0x48` 的 `0x4` 位 |

偏移与位掩码来自当前主程序元数据及原生 setter，不是新增按版本地址表。关闭此字段是切换引擎自身的鼠标模拟触摸配置，不是在插件中模拟引擎输入。

## 验证范围

- 全部既有隔离检查，以及新增原生开关和末次坐标检查。
- 对 65536 个 16 位配置值验证：清除该位不会修改任何相邻位。
- 默认对象身份、销毁状态、未识别开关、观察模式和重复应用检查。
- 实际生产 hover 回调的 end/cancel、正常位置、失焦和越界检查。
- 原触摸集合与参数完整转发检查；0.6.1 初始化顺序正反对照检查。
- 两个真实游戏版本的只读解析、release 独立加载、签名和无日志导入检查。

具体输出保存在 `validation/`。按钮点击效果仍需用户测试；本次没有运行游戏、替换已安装插件或保存游戏设置。
